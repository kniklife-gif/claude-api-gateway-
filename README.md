# Claude API Gateway (Cloudflare Workers)

A small Anthropic Messages API gateway. It keeps Anthropic credentials in Cloudflare Worker Secrets, authenticates callers with a separate bearer token, supports streaming without buffering the upstream body, and runs tests before deployment.

## Important limits

- This gateway is a proxy, not a way to obtain free Claude usage. Requests still consume the Anthropic API account's billing, quotas, and terms.
- The 10 key slots are for separately authorized credentials, not a way to bypass rate limits, quotas, or enforcement. The gateway never switches keys for HTTP 429, 401, 403, or other non-transient responses.
- For streaming requests, the gateway makes one upstream attempt. It does not retry after a stream request starts.
- For non-streaming requests, it tries at most 3 configured keys in slot order, and only retries on transport errors or HTTP 502/503/504. Retries can incur duplicate API charges; keep this behavior in mind.
- Request body is capped at 10 MiB. There is no request-body logging. The `/health` endpoint is intentionally unauthenticated and reveals only `ok`.
- Only `POST /v1/messages` and `POST /v1/messages/count_tokens` are accepted (plus `GET /health`). The Worker passes the raw JSON body through unchanged after validating that it is JSON. `model` and `messages` are required on `/v1/messages`.
- This gateway does not implement CORS. Claude Code is a server-side CLI and does not need browser CORS.

## 1. Run tests locally

Requires Node.js 22 or newer.

```bash
npm install
npm test
npx wrangler deploy --dry-run
```

## 2. Create Cloudflare Worker

1. Sign in to the Cloudflare Dashboard.
2. Open **Workers & Pages** → **Create** → **Worker**; create a Worker named `claude-api-gateway`.
3. You can deploy the source through GitHub Actions after connecting the repo; the workflow deploys `wrangler.toml` as the source of truth. Avoid maintaining conflicting code in the Dashboard editor.
4. In **Workers & Pages** → `claude-api-gateway` → **Settings** → **Variables and Secrets**, add secrets:
   - `GATEWAY_TOKEN`
   - `ANTHROPIC_API_KEY_1` through `ANTHROPIC_API_KEY_10` for credentials you are authorized to use.
5. Use **Encrypt** / **Secret** for each value, not a plain-text variable. You only need to add the key slots you actually use.
6. Save secrets. After deployment, the URL appears on the Worker overview page, typically `https://claude-api-gateway.<your-subdomain>.workers.dev`.
7. Confirm reachability with `curl https://YOUR-WORKER-URL/health`; expected response is `ok`. Health does not validate upstream credentials.

Generate a gateway token with a cryptographically secure random generator. On macOS/Linux: `openssl rand -hex 32`. On PowerShell: `$bytes = New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Fill($bytes); -join ($bytes | ForEach-Object { $_.ToString('x2') })`. Store it in a password manager and Cloudflare Secret `GATEWAY_TOKEN`; do not commit it or paste it into chats.

## 3. Configure GitHub Actions

In the GitHub repository, go to **Settings** → **Secrets and variables** → **Actions** → **New repository secret**. Add:

- `CLOUDFLARE_API_TOKEN`: a Cloudflare API token scoped to the target account with the minimum Workers deployment permissions required.
- `CLOUDFLARE_ACCOUNT_ID`: the account ID from Cloudflare's dashboard.

Do not add Anthropic keys or `GATEWAY_TOKEN` to GitHub for this workflow. They are runtime secrets stored in Cloudflare.

Push the project to the `main` branch. The workflow runs tests and a Wrangler dry-run first; the deploy job only runs after tests pass. Manual runs are available from **Actions** → **Test and Deploy Cloudflare Worker** → **Run workflow** on `main`.

## 4. Configure Claude Code

Anthropic documents `ANTHROPIC_BASE_URL` for an Anthropic-compatible gateway and `ANTHROPIC_AUTH_TOKEN` as a static gateway token sent as a bearer authorization value. Set these only in your local shell or a private Claude Code settings file; do not put the token in the repository.

### PowerShell (current terminal only)

```powershell
$env:ANTHROPIC_BASE_URL = "https://YOUR-WORKER-URL"
$env:ANTHROPIC_AUTH_TOKEN = "PASTE_YOUR_GATEWAY_TOKEN_HERE"
claude
```

### Bash / zsh (current terminal only)

```bash
export ANTHROPIC_BASE_URL="https://YOUR-WORKER-URL"
export ANTHROPIC_AUTH_TOKEN="PASTE_YOUR_GATEWAY_TOKEN_HERE"
claude
```

Claude Code sends the configured token as `Authorization: Bearer ...`; the Worker validates it and uses the stored Anthropic API key upstream. Keep the base URL without `/v1/messages` because Claude Code appends the API path.

For persistent configuration, use Claude Code's supported settings file `~/.claude/settings.json` with an `env` object. Protect the file with OS account permissions. Example:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://YOUR-WORKER-URL",
    "ANTHROPIC_AUTH_TOKEN": "YOUR_GATEWAY_TOKEN"
  }
}
```

On Windows, the user-level settings file is typically `%USERPROFILE%\.claude\settings.json`; verify this against your installed Claude Code version. Avoid storing secrets in project-level `.claude/settings.json` if the project is shared or committed.

### Minimal API test (PowerShell)

```powershell
$headers = @{
  Authorization = "Bearer $env:ANTHROPIC_AUTH_TOKEN"
  "Content-Type" = "application/json"
}
$body = @{
  model = "claude-sonnet-4-5"
  max_tokens = 16
  messages = @(@{ role = "user"; content = "Reply with OK" })
} | ConvertTo-Json -Depth 10
Invoke-RestMethod -Method Post -Uri "$env:ANTHROPIC_BASE_URL/v1/messages" -Headers $headers -Body $body
```

Use a model ID currently enabled for your Anthropic account. If the API call succeeds but Claude Code does not, update Claude Code and verify its gateway configuration options against Anthropic's current docs.

### Restore direct/default behavior

In the current PowerShell terminal:

```powershell
Remove-Item Env:ANTHROPIC_BASE_URL -ErrorAction SilentlyContinue
Remove-Item Env:ANTHROPIC_AUTH_TOKEN -ErrorAction SilentlyContinue
```

In Bash/zsh, run `unset ANTHROPIC_BASE_URL ANTHROPIC_AUTH_TOKEN`. If you put them in `settings.json`, remove those entries. Start a new terminal/session. Direct Anthropic access then requires the normal supported login/API setup for your account.

## 5. Credential failover policy

- **No failover:** HTTP 400/401/403/404/409/413/429 and other non-transient errors. In particular, 429 is returned to the caller so rate limits and quota enforcement are respected.
- **Eligible failover:** non-streaming transport errors and upstream 502/503/504 only. Maximum 3 attempts, in deterministic slot order.
- **No streaming retries:** a streaming request uses one key/attempt. Once a stream is returned, the body is passed through directly without buffering.
- **No hidden logs:** code does not log prompts, request bodies, tokens, API keys, or exception messages. Cloudflare platform-level observability may still include request metadata; review account logging settings and access controls.
- **Provider errors:** JSON error type/message are returned in a bounded response when parseable. No upstream response headers except content type and retry-after are forwarded.

## 6. Troubleshooting

- `401 Unauthorized`: `ANTHROPIC_AUTH_TOKEN` does not match Cloudflare `GATEWAY_TOKEN`.
- `503 No upstream API credentials`: add at least one `ANTHROPIC_API_KEY_n` Cloudflare Secret.
- `429`: upstream rate limit/quota; wait according to provider guidance. This gateway deliberately does not rotate keys.
- `502`: upstream network issue or unavailable Anthropic endpoint; check Cloudflare and Anthropic status.
- GitHub deploy failure: verify the account ID, API token scope, Worker name, and Actions secrets.
- To rotate secrets, replace them in Cloudflare Worker Secrets and redeploy if needed.
